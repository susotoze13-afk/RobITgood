# Ресёрч-агент — План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать работающего ресёрч-агента, который принимает тему, задаёт 3 уточняющих вопроса, исследует через Brave Search + FireCrawl и сохраняет структурированный отчёт в Google Docs.

**Architecture:** Агент реализован как `.claude/agents/research-agent.md` и вызывается координатором через `CLAUDE.md`. Три MCP обеспечивают инструменты: Brave Search (широкий поиск 10-15 источников), FireCrawl (полный текст топ-5 страниц), Google Drive (создание отчёта).

**Tech Stack:** Claude Code Agent Teams, MCP серверы через npx, Node.js

## Task 2: Настроить Brave Search MCP

**Files:**
- Изменить: `c:\Program Files\Git\Day1\settings.json`

- [ ] **Шаг 1: Добавить BRAVE_API_KEY и секцию mcpServers в settings.json**

  Открыть `settings.json` и сделать два изменения (заменить `ВАШ_BRAVE_КЛЮЧ` на реальный ключ):

  **Изменение 1** — добавить строку в существующий блок `"env"` после `"NODE_TLS_REJECT_UNAUTHORIZED": "0"`:
  ```json
  "BRAVE_API_KEY": "ВАШ_BRAVE_КЛЮЧ"
  ```

  **Изменение 2** — добавить новый блок `"mcpServers"` после закрывающей `}` блока `"env"`, перед `"permissions"`:
  ```json
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "ВАШ_BRAVE_КЛЮЧ"
      }
    }
  },
  ```

- [ ] **Шаг 2: Перезапустить Claude Code и проверить подключение**

  Полностью закрыть и открыть Claude Code. В чате выполнить:
  ```
  /mcp
  ```
  Ожидаемый результат: `brave-search` со статусом `✓ connected`.

- [ ] **Шаг 3: Протестировать инструмент**

## Task 4: Настроить Google Drive MCP

**Files:**
- Изменить: `c:\Program Files\Git\Day1\settings.json`
- Создать: `C:\Users\1\.config\mcp-gdrive\credentials.json` (через Google Cloud Console)

- [ ] **Шаг 1: Создать проект в Google Cloud Console**

  1. Открыть https://console.cloud.google.com/
  2. Создать новый проект — назвать "AI Secretary"
  3. Перейти в "APIs & Services" → "Library"
  4. Найти "Google Drive API" → нажать "Enable"
  5. Найти "Google Docs API" → нажать "Enable"

- [ ] **Шаг 2: Настроить OAuth consent screen**

  1. Перейти в "APIs & Services" → "OAuth consent screen"
  2. Выбрать "External" → нажать "Create"
  3. Заполнить: App name = "AI Secretary", User support email = ваш email
  4. Нажать "Save and Continue" три раза до конца

- [ ] **Шаг 3: Создать OAuth credentials**

  1. Перейти в "APIs & Services" → "Credentials"
  2. Нажать "+ Create Credentials" → "OAuth client ID"
  3. Application type: "Desktop app"
  4. Name: "AI Secretary MCP"
  5. Нажать "Create"
  6. Нажать "Download JSON" → сохранить файл

  Создать папку и скопировать файл:
  ```powershell
  New-Item -ItemType Directory -Force -Path "C:\Users\1\.config\mcp-gdrive"
  Copy-Item "C:\Users\1\Downloads\client_secret_*.json" "C:\Users\1\.config\mcp-gdrive\credentials.json"
  ```

- [ ] **Шаг 4: Добавить gdrive в mcpServers**

  Добавить в `mcpServers` в `settings.json`:
  ```json
  "gdrive": {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-gdrive"],
    "env": {
      "GDRIVE_CREDENTIALS_PATH": "C:\\Users\\1\\.config\\mcp-gdrive\\credentials.json",
      "GDRIVE_TOKEN_PATH": "C:\\Users\\1\\.config\\mcp-gdrive\\token.json"
    }
  }
  ```

- [ ] **Шаг 5: Пройти OAuth авторизацию**

  Перезапустить Claude Code. При первом запросе `/mcp` или при первом использовании gdrive инструмента — браузер откроет страницу Google с запросом разрешений. Нажать "Разрешить". Токен сохранится автоматически в `token.json`.

- [ ] **Шаг 6: Протестировать инструмент**

  В чате написать: "Создай Google Doc с названием 'Тест' и текстом 'Система работает'"

  Ожидаемый результат: Claude создаёт документ и возвращает ссылку вида `https://docs.google.com/document/d/...`

## Task 5: Создать файл агента research-agent.md

**Files:**
- Создать: `c:\Program Files\Git\Day1\.claude\agents\research-agent.md`

- [ ] **Шаг 1: Создать директорию**

  ```bash
  mkdir -p "c:/Program Files/Git/Day1/.claude/agents"
  ```

- [ ] **Шаг 2: Создать файл агента**

  Создать `c:\Program Files\Git\Day1\.claude\agents\research-agent.md`:

  ````markdown
  ---
  name: research-agent
  description: Проводит глубокое исследование по заданной теме. Использует Brave Search для широкого поиска и FireCrawl для детального анализа страниц. Создаёт структурированный отчёт в Google Docs на русском языке с разделом решений (3 платных + 3 бесплатных сервиса). Вызывать при любых запросах на исследование, поиск информации, анализ темы, поиск сервисов и решений.
  ---

  Ты — Ресёрч-агент системы AI-Секретарь. Проводишь глубокие исследования и создаёшь структурированные отчёты в Google Docs.

  ## Обязательный порядок работы

  ### Шаг 1: Уточняющие вопросы

  Задавай строго по одному вопросу и жди ответа перед следующим:

  **Вопрос 1:** "Какую проблему хотите решить?"
  *(дождаться ответа пользователя)*

  **Вопрос 2:** "Опишите целевую аудиторию, для которой вы хотите решить эту проблему."
  *(дождаться ответа пользователя)*

  **Вопрос 3:** "Какая глубина исследования нужна?
  - Обзор — 5 источников
  - Стандарт — 10 источников
  - Глубокий — 15+ источников"
  *(дождаться ответа пользователя)*

  ### Шаг 2: Исследование

  После получения всех трёх ответов немедленно начинай исследование:

  1. Сформулируй 3-5 поисковых запросов на основе темы и проблемы пользователя (на русском и английском)
  2. Для каждого запроса вызови `brave_web_search`
     - Обзор: собери ~5 уникальных источников
     - Стандарт: собери ~10 уникальных источников
     - Глубокий: собери 15+ уникальных источников
  3. Из всех результатов выбери топ-5 наиболее релевантных URL
  4. Для каждого из 5 URL вызови `firecrawl_scrape` чтобы получить полный текст страницы
  5. Проанализируй и синтезируй всю найденную информацию

  ### Шаг 3: Создание отчёта в Google Docs

  Создай Google Doc через доступный gdrive инструмент.

  **Название документа:** `[Тема исследования] — Исследование [ДД.ММ.ГГГГ]`

  **Структура содержимого** (ТОЛЬКО на русском языке, независимо от языка источников):

  ```
  # [Тема исследования]
  Дата: [ДД.ММ.ГГГГ] | Глубина: [выбранная] | Аудитория: [ответ пользователя]

  ## 1. Краткий вывод
  [2-3 абзаца: конкретный ответ на вопрос "какую проблему решаем". Без воды — только суть.]

  ## 2. Ключевые факты
  — [конкретный факт из источников]
  — [конкретный факт из источников]
  — [минимум 5 фактов]
  ...

  ## 3. Детальный анализ
  ### [Аспект/подтема 1]
  [Анализ на основе источников, 2-4 абзаца]

  ### [Аспект/подтема 2]
  [Анализ на основе источников, 2-4 абзаца]

  ### [Аспект/подтема 3 — при необходимости]
  [Анализ на основе источников]

  ## 4. Решения

  ### Платные сервисы (3 варианта)
  | Сервис | Цена | Что решает | Ссылка |
  |--------|------|------------|--------|
  | [название] | [цена/мес] | [конкретное описание] | [url] |
  | [название] | [цена/мес] | [конкретное описание] | [url] |
  | [название] | [цена/мес] | [конкретное описание] | [url] |

  ### Бесплатные сервисы (3 варианта)
  | Сервис | Ограничения | Что решает | Ссылка |
  |--------|-------------|------------|--------|
  | [название] | [конкретные лимиты] | [конкретное описание] | [url] |
  | [название] | [конкретные лимиты] | [конкретное описание] | [url] |
  | [название] | [конкретные лимиты] | [конкретное описание] | [url] |

  ## 5. Источники
  1. [Точное название страницы] — [полный URL]
  2. [Точное название страницы] — [полный URL]
  ...
  ```

  ### Шаг 4: Ответ пользователю

  После успешного создания документа отправь пользователю:
  1. Прямую ссылку на Google Doc
  2. Краткое резюме (2-3 предложения): что исследовалось и главный практический вывод

  ## Правила (обязательные)

  - Весь текст отчёта ВСЕГДА на русском языке — даже если все источники на английском
  - Раздел "4. Решения": строго 3 платных И 3 бесплатных сервиса — не больше, не меньше
  - Никогда не выдумывай факты и не придумывай несуществующие сервисы — только реальные данные из источников
  - После получения ответов на все 3 вопроса — сразу начинай исследование, не задавай дополнительных вопросов
  - Если не можешь найти достаточно источников — честно сообщи пользователю и объясни почему
  ````

## Task 6: Создать CLAUDE.md (координатор)

**Files:**
- Создать: `c:\Program Files\Git\Day1\CLAUDE.md`

- [ ] **Шаг 1: Создать CLAUDE.md**

  Создать файл `c:\Program Files\Git\Day1\CLAUDE.md`:

  ```markdown
  # AI-Секретарь — Инструкции координатора

  Ты — координатор системы AI-Секретарь. Читаешь сообщение пользователя и определяешь, какой специализированный агент нужен. Никогда не выполняешь задачи агентов самостоятельно — всегда делегируешь.

  ## Команда агентов

  ### Ресёрч-агент (`research-agent`)

  **Когда вызывать** — при любом из следующих запросов:
  - "исследуй", "сделай ресёрч", "найди информацию", "изучи тему", "сделай анализ"
  - "что такое [X]", "как работает [X]", "расскажи про [X]"
  - "найди сервисы / инструменты / решения для..."
  - "конкурентный анализ", "анализ рынка", "обзор рынка"
  - "собери информацию по...", "сделай обзор темы..."

  **Правило:** НИКОГДА не отвечай сам на исследовательские запросы — всегда делегируй ресёрч-агенту.

  ---

  ## Архитектура системы AI-Секретарь

  ```
  Пользователь
      ↓ сообщение
  Координатор (CLAUDE.md)
      ↓ распознаёт тип задачи
      ├── Исследование, поиск информации → research-agent
      ├── Документы, договоры, акты    → [будет добавлен: lawyer-agent]
      ├── Финансы, расходы, доходы     → [будет добавлен: finance-agent]
      └── Календарь, встречи           → [будет добавлен: calendar-agent]
  ```

  ## Правила координации

  1. Прочитай сообщение пользователя полностью
  2. Определи тип задачи по триггерам выше
  3. Вызови агента через механизм суб-агентов
  4. Передай агенту полный контекст запроса пользователя
  5. Если задача не подходит ни одному агенту — выполни сам и уточни у пользователя
  ```
