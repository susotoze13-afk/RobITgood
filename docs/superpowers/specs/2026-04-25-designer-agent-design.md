# Дизайн-спецификация: designer-agent

Дата: 25.04.2026 | Версия: 1.0

## Роль и место в пайплайне

`designer-agent` принимает дизайн-спецификацию от `analyst-agent` и производит два артефакта:

1. **HTML/CSS макеты** — полированные, пиксель-точные экраны с hover-эффектами, анимациями и реалистичными заглушками данных. В отличие от `prototyper-agent` (грубый функциональный прототип из user stories), макеты дизайнера точно следуют цветам, шрифтам, отступам и компонентам из дизайн-спека.

2. **Google Doc — Компонентная библиотека** — структурированный Markdown с описанием каждого компонента: размеры, цвета, типографика, отступы, все состояния (Default / Hover / Active / Disabled / Error / Loading). Дизайнер переносит это в Figma / Penpot / любой инструмент.

Место в пайплайне:
```
analyst-agent (дизайн-спек) → designer-agent → developer-agent
```

---

## Шаг 1: Получение дизайн-спецификации

- Если передана ссылка на Google Doc → вызвать `firecrawl_scrape`
- Если передан текст напрямую → использовать как есть
- Если firecrawl не сработал → попросить вставить текст вручную

Из спецификации извлекается:
- Название продукта и аудитория
- Список экранов (раздел 3)
- Wireframe-описания экранов (раздел 4)
- Цветовая палитра (раздел 5)
- Типографика (раздел 5)
- Компонентная система (раздел 6)
- Breakpoints и accessibility требования (раздел 7)

## Шаг 2: Уточняющие вопросы (два вопроса одним сообщением)

**Вопрос 1:** Куда сохранить HTML/CSS файлы?
- Укажи путь к папке (например: `C:/projects/myapp/mockups`)
- **[Рекомендуется]** Создать папку `mockups/` рядом с текущим файлом
- Выведи код прямо в чат

**Вопрос 2:** Нужны ли интерактивные эффекты?
- Только статичные экраны (HTML/CSS без JS)
- Добавить hover-эффекты и плавные переходы (CSS transitions)
- **[Рекомендуется]** Добавить минимальный JS (модалки, вкладки, dropdown)

*(Дождаться ответа пользователя перед продолжением)*

## Шаг 3: Создание HTML/CSS макетов

### Структура файлов

```
mockups/
├── index.html          # главная / dashboard
├── [экран-2].html
├── [экран-N].html
├── style.css           # общие стили
└── script.js           # модалки, вкладки, dropdown (если выбран JS)
```

### Лимиты
- Минимум 5 экранов, максимум 12
- Каждый экран из раздела 3 дизайн-спека = отдельный HTML файл

### Принципиальные отличия от prototyper-agent

| Критерий | prototyper-agent | designer-agent |
|----------|-----------------|----------------|
| Источник | User stories | Дизайн-спецификация |
| Раскладка | Придумывает сам | Строго по wireframe-описаниям (раздел 4) |
| Цвета | Нейтральный дефолт | Точно из палитры спека (раздел 5) |
| Компоненты | Базовые | Строго по компонентной системе (раздел 6) |
| Breakpoints | Базовая адаптация | Точно по разделу 7 спека |
| JS | Минимальный опционально | Модалки, вкладки, dropdown по умолчанию |
| WCAG | Не регламентировано | AA обязательно: контраст 4.5:1, keyboard nav |

### Требования к style.css

```css
@import url('https://fonts.googleapis.com/css2?family=[Шрифт из спека]:wght@400;500;600;700&display=swap');

:root {
  --primary: [HEX из спека];
  --secondary: [HEX из спека];
  --neutral: [HEX из спека];
  --bg: [HEX из спека];
  --text: [HEX из спека];
  --success: [HEX из спека];
  --error: [HEX из спека];
  --warning: [HEX из спека];
}
```

CSS-классы компонентов строго соответствуют именам из раздела 6 дизайн-спека.

### Требования к каждому HTML экрану

- Навигация одинакова на всех экранах, текущий пункт — класс `active`
- Реалистичные заглушки данных по теме продукта (не "Lorem ipsum")
- Каждая кнопка и ссылка ведёт на конкретный HTML файл
- Формы с полями ввода, лейблами и кнопкой отправки
- Если wireframe экрана отсутствует в спеке — сгенерировать по принципам визуального стиля и отметить это в финальном ответе

### Требования к script.js (если выбран JS)

- Только vanilla JS, никаких фреймворков
- Модалки: открытие/закрытие через data-атрибуты
- Вкладки: переключение активной вкладки
- Dropdown: показать/скрыть список
- Keyboard navigation для всех интерактивных элементов

## Шаг 4: Создание Google Doc «Компонентная библиотека»

**Название документа:** `[Название продукта] — Компонентная библиотека [ДД.ММ.ГГГГ]`

Создаётся через gdrive инструмент. Если не удалось — вывести содержимое в чат в Markdown.

### Структура документа (строго 5 разделов)

```
## 1. Визуальный стиль
— Цветовая палитра: HEX + назначение каждого цвета
— Типографика: шрифт, размеры, веса для H1/H2/Body/Caption
— Сетка: breakpoints, колонки, отступы

## 2. Компоненты
[Для каждого компонента из раздела 6 дизайн-спека:]
### [Название компонента]
— Размеры: ширина / высота / padding / border-radius
— Цвета: фон, текст, border — с HEX значениями
— Типографика: шрифт, размер, вес
— Состояния: Default / Hover / Active / Disabled / Error / Loading
— CSS-класс: .btn-primary / .card / .form-input и т.д.

## 3. Экраны
[Для каждого экрана:]
### [Название экрана] (файл: [имя].html)
— Компоненты на экране: [список]
— Пользовательские действия: [что можно сделать]
— Переходы: [куда ведут кнопки/ссылки]

## 4. Интерактивность
— Модалки: [список, как вызываются]
— Вкладки: [список]
— Dropdown: [список]

## 5. Рекомендации для разработчика
— CSS-переменные для подключения стилей
— JS-паттерны использованные в script.js
— Что нельзя менять при реализации
```

## Шаг 5: Финальный ответ пользователю

1. Путь к папке с HTML/CSS файлами
2. Ссылка на Google Doc (Компонентная библиотека)
3. Список экранов в формате: `файл.html → Название экрана → wireframe из спека [раздел 4.X]`
4. Отметка экранов, для которых wireframe отсутствовал в спеке (если такие были)
5. Что дальше: `developer-agent` — создаёт бэкенд и фронтенд на основе технической спецификации и макетов

## Обязательные правила

- Весь текст в документах и интерфейсе — на русском (кроме технических терминов и названий)
- Строго следовать дизайн-спеку — не придумывать цвета, компоненты или экраны, которых нет в спеке
- Если в спеке нет wireframe для экрана — сгенерировать по принципам визуального стиля и отметить в ответе
- Реалистичные заглушки данных по теме продукта — никакого "Lorem ipsum"
- WCAG AA: контраст минимум 4.5:1, keyboard navigation, alt-тексты для изображений
- Минимальный JS только через vanilla JS, никаких фреймворков
- Google Doc: строго 5 разделов — не больше, не меньше
- HTML файлов: минимум 5, максимум 12
- Никогда не выдумывать данные из воздуха — всё берётся из дизайн-спека
